# Обновление документации проекта

## Когда запускать
- После **3+ коммитов** в core-код
- После **исправления бага** — добавить в LESSONS_LEARNED
- После **завершения фичи** — обновить CURRENT_STATUS
- После **TypeScript/Vercel ошибок** — задокументировать решение
- Перед **началом новой сессии** — проверить CURRENT_STEP

## Чеклист обновления

### 1. LESSONS_LEARNED.md
```
### Урок N: [Краткое описание]
**Проблема:** [Что случилось]
**Решение:** [Как исправили]
**Предотвращение:** [Как избежать в будущем]
```

### 2. CURRENT_STATUS.md
- Обновить дату
- Изменить прогресс-бары
- Перенести завершённые задачи в "Готово"
- Добавить новые проблемы в "Текущие проблемы"

### 3. CURRENT_STEP.md
- Обновить дату
- Изменить статус шага
- Добавить завершённые подзадачи

### 4. ROADMAP/03-CURRENT_STATUS.md
- Обновить проценты выполнения

## Правило
> **Если я сделал значимое изменение — я ДОЛЖЕН обновить документацию ДО следующего ответа пользователю.**
