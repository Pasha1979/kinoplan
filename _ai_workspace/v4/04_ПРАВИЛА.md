## Скоуп и потерянность
- «Если я не указал что изменения надо применить ко всему — меняешь только то, над чем конкретно работаем» (L-41, R-правило скоупа)
- «Следи что б ни чего важного не потерялось» — режим ноль потерь (R-11)
- Заглушки не удалять до реализации модуля (R-3); каждая заглушка = задача.

## Работа
- Обсуждение → Согласование → только потом код; один шаг за раз (R-10, R-12)
- Сценарий — первым, «доделать до ума перед другими модулями» (R-1, R-80)
- Ответвления: идея/баг → выполняем и возвращаемся в точку фазы, всё фиксируем (R-9); запрещено прыгать между фазами (R-8)
- Приоритеты: P0 краш/потеря данных → немедленно; P1 функциональный баг → ответвление; P2 UX → в плане (R-34)

## Гейт изменений
- Перед коммитом: `npm run build` зелёный + git diff осмотрен; после: commit → push → проверка Vercel-деплоя (R-процесс, L-7, R-82)
- Секреты — только в .env/секретах окружения, никогда в репозитории и не «в память AI» (R-53, L-36)

## Общение
- Только русский, простым языком: «нажми → увидишь → произойдёт», не «компонент рендерит» (R-14, R-17)
- Короткие вопросы с вариантами ответов; 2–3 варианта решения (R-10)
- Докладывать ссылки dev (localhost:5173) + прод (kinoplan.vercel.app) (R-79)

## Протокол идей и статус
- Каждая идея/указание/замечание → сразу запись с дословной цитатой, датой, ID; подтверждение «Записал: I-…» (R-2, R-6, протокол Ф5.8)
- Статус выполненных работ обновляется без напоминаний (R-7)
- Помощь (?) на каждом модуле; новые модули — своя HelpModal (R-78, R-81→R-84)

## Архитектура
- Local-first; React → IPC → SQLite (React не трогает БД напрямую) (D-41)
- Компоненты не импортируют localStorage/fetch/axios — только сервисы (D-41)
- Миграции для схемы БД; эталоны: exemplar-service.ts / exemplar-component.tsx (R-47)
