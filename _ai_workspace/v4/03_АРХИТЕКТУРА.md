# 03 · АРХИТЕКТУРА (текущая правда)
> Дата: 12.11.2026 · Источники: package.json, src/, ARCHITECTURE_GUARDIAN, ПРАВИЛА_АРХИТЕКТУРЫ, D-25, D-41

## Стек (реализовано)
- React 19 + TypeScript + Vite · Tailwind v4 · Zustand (+persist, Immer, нормализация)
- Tiptap/ProseMirror — редактор сценария (scene_header/action/character/dialog/parenthetical/transition + scene-parenthetical)
- PouchDB — локальная персистенция (debounce, flush, pending-read, beforeunload); память-адаптер для тестов
- @dnd-kit — drag&drop · Vitest + Testing Library · Playwright (e2e)
- Vite manualChunks — разделённый бандл (vendor, script-editor, store, модули)
- Vercel — хостинг веб-версии (kinoplan.vercel.app); dev: localhost:5173

## План, НЕ реализовано (в package.json нет)
- Electron (десктоп), Capacitor (мобайл), SQLite — целевая платформа
- Синхронизация WebDAV/P2P, серверная часть, реальная коллаборация
- AI (Groq/Ollama) — Ф3+

## Границы (жёсткие правила)
- Local-first: всё работает оффлайн (D-41)
- React → только через сервисы/репозитории; компоненты не импортируют localStorage/fetch/axios (D-41)
- React никогда не трогает SQLite напрямую — только IPC (будущее) (D-25)
- Схема БД меняется миграциями; эталоны: context/exemplar-service.ts, exemplar-component.tsx (R-47)
- Модули — изолированные страницы со своими сторами/репозиториями
- Данные проекта всегда скоупнуты projectId; sceneId = UUID, не номер сцены (D-аудит)

## Данные
- Хранилище: localStorage-ключи `kinoplan_*` мигрируются в PouchDB; серии исторически `_s${N}`
- scenes: UUID в attrs/data-scene-id; groups/links на уровне Script
- Экспорт `.kinoplan`: schemaVersion + project + scripts + контент; импорт регенерирует ID
