## Инцидент: 429 при установке vitest.explorer
- Симптом: `Error while installing extension vitest.explorer: Server returned 429` (временный лимит магазина при подряд идущих установках).
- Решение: пауза ~2 минуты и повтор — установилось из магазина. Запасной путь (не понадобился): .vsix с open-vsx.org/api/vitest/explorer/latest -> `--install-extension <файл.vsix>`.
- Урок: при установке нескольких расширений подряд делать паузы; при 429 просто подождать и повторить.

- Ловушки:
  - `--python` в setup перекрывает venv в генереном конфиге — ставить без него после создания venv, иначе command укажет на base-интерпретёр без mcp SDK.
  - `grab_and_export` игнорирует `folder_path` — Resolve пишет стиллы в `C:\Users\user\Documents\resolve-stills`, копировать вручную. PNG 1920x1080 ~6 МБ, в ответе MCP инлайнится base64 (тяжело).
  - GrabStill иногда падает retryable-ошибкой после grade-мутаций — просто повторить.
  - `TimelineItem.AddVersion` переключает клип на НОВУЮ версию — прежняя остаётся нетронутой (restore-point). Мутации версий работают только со страницы color.
  - ffmpeg не на PATH — `timeline_frame capture` с `max_width` отказывает; без max_width работает.
- Доказанный пайплайн покраски (тест MCP_TEST): open_page color → grade_boundary_report → grade_version_snapshot → probe_node_graph → set_current_timecode → grab_and_export (before) → add_version (рабочая) → safe_set_cdl dry_run → safe_set_cdl → grab_and_export (after) → численное сравнение PNG. Восстановление: grade_version_restore "Version 1".
- Ограничения API (честно): нельзя создавать новые ноды/окна/кривые/квалифаеры/трекинг из структурированных параметров — только CDL на существующих нодах, LUT на существующую ноду, целые грейды через .drx/copy.
