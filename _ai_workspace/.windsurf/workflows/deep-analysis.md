# 🔍 Глубокий Анализ Кода

## Когда использовать

### Автоматические триггеры:
- После 3+ значимых коммитов в core-компоненты
- После добавления новой фичи (SmartType, DragDrop, etc.)
- После рефакторинга структуры
- Раз в неделю если были изменения
- Перед переходом к новой фазе проекта

### Ручные триггеры:
- Подозрение на скрытые баги
- Падение производительности
- Неожиданное поведение

## Чеклист анализа

### 1. Архитектура и логика
- [ ] Нет ли бесконечных циклов/рекурсий?
- [ ] Нет ли race conditions?
- [ ] Корректная обработка edge cases?
- [ ] Состояния компонентов консистентны?

### 2. Производительность
- [ ] Есть debounce/throttle где нужно?
- [ ] Нет ли лишних ререндеров?
- [ ] Оптимальная сложность алгоритмов?
- [ ] Нет ли утечек памяти?

### 3. UX и поведение
- [ ] Позиция курсора сохраняется?
- [ ] Undo/Redo работает корректно?
- [ ] Нет ли неожиданных авто-изменений?

### 4. Консистентность данных
- [ ] Нет ли дублирования источников правды?
- [ ] Синхронизация состояний корректна?

### 5. Код-стайл и техдолг
- [ ] Нет ли дублирования кода?
- [ ] Хардкод вынесен в конфигурацию?
- [ ] Типы TypeScript корректны?

## Процесс анализа

1. **Подготовка**
   - Проверить дату последнего анализа в DEEP_ANALYSIS_SYSTEM.md
   - Посмотреть git log с тех пор
   - Определить какие компоненты изменились

2. **Анализ**
   - Читать core-компоненты полностью
   - Искать скрытые зависимости
   - Проверить циклы жизни компонентов
   - Тестировать edge cases

3. **Документирование**
   - Записать найденные проблемы
   - Оценить severity (🚨 критично / ⚠️ средне / 💡 минор)
   - Предложить решения

4. **Исправление**
   - Фиксить критичные проблемы
   - Планировать средние на потом
   - Обновить DEEP_ANALYSIS_SYSTEM.md

## Обновление системы

После анализа ОБЯЗАТЕЛЬНО:
// turbo
- Обновить дату в DEEP_ANALYSIS_SYSTEM.md
- Добавить запись в Историю анализов
- Установить дату следующего анализа
