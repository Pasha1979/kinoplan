## Сессия 30.05.2026 — SmartType для шапки сцены

### Урок 1: Автонумерация мешала вводу
**Проблема:** Переписывала номера сцен при каждом изменении, мешая пользователю.
**Решение:** Убрать из `handleContentChange`, оставить только при создании новой сцены.
**Предотвращение:** Не модифицировать пользовательский ввод без явного запроса.

### Урок 2: Пробел не работал с autoCompleteSceneHeader
**Проблема:** `autoCompleteSceneHeader` заменял текст при каждом изменении, не давая набрать пробел.
**Решение:** Заменить на SmartType (подсказки без автовставки) — пользователь сам выбирает.
**Предотвращение:** Никогда не менять ввод пользователя автоматически.

### Урок 3: Конфликт подсказок smartType и sceneHeaderSuggestions
**Проблема:** Два разных источника подсказок конфликтовали и мешали друг другу.
**Решение:** `sceneHeaderSuggestions` приоритетнее — закрывать smartType, если есть шапка сцены.
**Предотвращение:** Иерархия контекста: конкретный (шапка) > общий (любой блок).

### Урок 4: applySuggestion стирала текст
**Проблема:** Неправильно находила последнее слово для замены.
**Решение:** Использовать `lastIndexOf(' ')` для точного определения границы слова.
**Предотвращение:** Тестировать replace на разных длинах текста.

### Урок 5: Блок участников создавался внизу
**Проблема:** Использование устаревшего индекса при добавлении нового блока.
**Решение:** Использовать `setBlocks(prevBlocks => ...)` для актуального индекса.
**Предотвращение:** Всегда использовать функциональную форму setState при зависимости от предыдущего состояния.

## Сессия 01.06.2026 — Архитектурный аудит

### Урок 6: Дублирование интерфейса Scene (АРХИТЕКТУРНАЯ ОШИБКА)
**Проблема:** `SceneNavigator.tsx` имел свой `interface Scene`, дублирующий `Scene` из `scriptStore.ts`. При изменении одного — другой устаревал. Поле `pageCount` vs `pages` вызвало ошибку TypeScript.
**Решение:** Удалить дубль, импортировать `type { Scene } from '../store/scriptStore'`.
**Предотвращение:** Никогда не дублировать интерфейсы/типы! Всегда импортировать из единого источника (store/types).

### Урок 7: Завершение сессии без проверки сохранения (ПРОЦЕССНАЯ ОШИБКА)
**Проблема:** Сказал "сессия завершена", но не убедился что все изменения сохранены и синхронизированы с git. Пользователь заметил что изменения не были закоммичены.
**Решение:** ВСЕГДА проверять `git status` перед завершением сессии. Если есть изменения — коммитить и пушить.
**Предотвращение:** Правило: "Завершение сессии = git status clean + git push successful". Без этого сессия не завершена!

## Сессия 01.06.2026 — Финальные фиксы форматирования и стабилизация

### Урок 10: Слишком строгие паттерны ломают диалоги
**Проблема:** Сокращенные формы "И" и "И." в паттерне шапки сцены ловили начало слов в диалогах ("И что?", "И ты..."), создавая ложные сцены.
**Решение:** Убрать сокращения — только полные формы "ИНТ", "ЭКСТ", "ИНТ-ЭКСТ". Требовать пробел + заглавную букву после.
**Предотвращение:** Паттерны должны быть максимально специфичны. Если слово может встретиться в обычном тексте — оно не должно быть триггером.

### Урок 11: CSS max-width сжимает текст до вертикали
**Проблема:** `max-width: calc(100% - 3.75cm - 3.75cm)` для диалога сжимал блок до ~8cm, текст разбивался по буквам вертикально.
**Решение:** Убрать `max-width` и `box-sizing`. Диалог должен занимать доступное пространство с отступами.
**Предотвращение:** Никогда не ограничивать width блока с текстом если есть padding'и по бокам.

### Урок 12: Padding-left мешает центрированию
**Проблема:** `padding-left: 6.75cm` с `text-align: center` создавал смещение — текст центрировался в оставшемся узком пространстве справа.
**Решение:** Для центрирования использовать `width: 100%` + `text-align: center`, а не padding с одной стороны.
**Предотвращение:** Для центрирования всегда использовать симметричные отступы или проценты ширины.

### Урок 13: SmartType везде мешает в диалогах
**Проблема:** Подсказки ИНТ/ЭКСТ/время срабатывали во всех блоках, включая диалоги, где они не нужны.
**Решение:** Ограничить SmartType только `sceneHeader`. Другие блоки — `closeSuggestions()`.
**Предотвращение:** Контекстные подсказки должны проверять текущий тип блока перед показом.

### Урок 14: Несинхронизированные паттерны — ложные сцены
**Проблема:** Автоопределение блока использовало один паттерн, а парсер сцен — другой. Диалоги попадали в список сцен.
**Решение:** Синхронизировать паттерны в `autoDetectBlockType` и `parseScenes`. Один источник истины.
**Предотвращение:** Если есть два места с одинаковой логикой — выносить в константу или функцию.

## Сессия 30.05.2026 — SmartType для шапки сцены

### Урок 1: Автонумерация мешает вводу
**Проблема:** Автонумерация пересчитывала номера при КАЖДОМ изменении текста, что переписывало то что пишет пользователь.
**Решение:** Убрать автонумерацию из `handleContentChange`. Оставить только при создании новой сцены (Enter/Tab).
**Предотвращение:** Всегда проверять — изменение state пересоздаёт ли блоки? Если да — вешать только на явные действия (создание, удаление).

### Урок 2: Пробел не работал
**Проблема:** `autoCompleteSceneHeader` вызывалась при каждом изменении текста и заменяла «И» на «ИНТ.» даже когда пользователь хотел просто написать слово с пробелом.
**Решение:** Заменить автовставку на SmartType (подсказки без автовставки). Пользователь сам решает — нажать Tab или нет.
**Предотвращение:** Никогда не заменять текст без явного действия пользователя. Подсказка ≠ принудительная замена.

### Урок 3: Конфликт двух систем подсказок
**Проблема:** `smartType` (для персонажей) и `sceneHeaderSuggestions` (для шапки) работали одновременно. При нажатии Tab — `smartType` перехватывал событие и не давал применить подсказку шапки.
**Решение:** Сделать `sceneHeaderSuggestions` приоритетнее. Проверять сначала его, потом `smartType`.
**Предотвращение:** Если есть несколько систем с одинаковыми триггерами (Tab/Enter) — всегда определять приоритет.

### Урок 4: applySuggestion стирала текст
**Проблема:** `applySuggestion` неправильно находила «последнее слово» — использовала `split(/\s+/)` вместо `lastIndexOf(' ')`, что приводило к удалению части текста.
**Решение:** Использовать `lastIndexOf(' ')` для поиска начала последнего слова.
**Предотвращение:** При замене текста — всегда проверять на примерах с пробелами, точками, спецсимволами.

### Урок 5: Блок участников создавался внизу
**Проблема:** Блок `scene_cast` создавался в конце списка блоков вместо сразу после шапки, потому что использовался устаревший массив `blocks` из замыкания.
**Решение:** Использовать функциональную форму `setBlocks(prevBlocks => ...)` для актуального индекса.
**Предотвращение:** Всегда использовать функциональную форму setState если новое значение зависит от предыдущего.

### Урок 8: Нереализованные кнопки — ставить заглушки
**Проблема:** Кнопки "Сохранить", "Настройки", панель "Заметки" — всё были нерабочими элементы без объяснения.
**Решение:** Добавить `alert()` с сообщением что функция в разработке. Заменить панель заметок на экран "В разработке".
**Предотвращение:** Любая кнопка без функции = заглушка с объяснением. Не оставлять нерабочие элементы.

### Урок 7: Предустановленные сцены + null
**Проблема:** DEMO_SCENES показывались при "Написать с нуля". После замены на пустой массив `scenes`, `selectedScene` стал `null` — краш при обращении к `.number`, `.id`.
**Решение:** Заменить `DEMO_SCENES` на `[]`. Добавить `?.` (optional chaining) во все места где используется `selectedScene`.
**Предотвращение:** При замене данных-заглушки на пустой массив — всегда проверять все места где использовалась заглушка. Всегда добавлять fallback для null.

### Урок 6: Не сохранялось в _ai_workspace
**Проблема:** Я забыл сохранять прогресс в документацию. Тратилось время на повторное объяснение, терялся контекст.
**Решение:** Создать чёткую структуру (CURRENT_STATUS, CURRENT_STEP, CHECKLIST, LESSONS_LEARNED) и проверять по чек-листу после каждого шага.
**Предотвращение:** Правило «9 пунктов» из CHECKLIST.md — проверять документацию после каждого шага.

### Урок 9: Кириллица в пути файла — создание "призрачной" папки
**Проблема (31.05.2026):** При создании файла `ScriptEditorTiptap.tsx` через write_to_file, я случайно использовал кириллицу в пути: `kinopлан` вместо `kinoplan`. Это создало вторую папку с похожим именем, в которую попал новый файл. Все последующие команды (npm install, git add, TypeScript проверка) искали файл в правильной папке `kinoplan` и не находили его.

**Последствия:**
- TypeScript ошибки: "Cannot find module"
- Невозможность запустить dev сервер
- Потеря времени на отладку (15+ минут)
- Конфузия в файловой системе

**Решение:** 
1. Удалить "призрачную" папку `kinopлан`
2. Пересоздать файл в правильной папке `kinoplan`
3. Перезапустить dev сервер

**Корневые причины:**
1. **Автокомплит кириллицы:** IDE или система предложила кириллический вариант пути
2. **Невнимательность:** Не проверил путь перед подтверждением
3. **Отсутствие валидации:** write_to_file не проверяет, существует ли путь

**Предотвращение (заповеди):**
1. **Всегда копировать путь:** Использовать `read_file` или `list_dir` для получения точного пути, не писать руками
2. **Проверять после создания:** Сразу после `write_to_file` делать `read_file` для проверки что файл на месте
3. **Только ASCII в путях:** Никогда не использовать кириллицу, пробелы, спецсимволы в путях
4. **Проверять npm install:** Если пакеты установились, но TypeScript не видит модули — проверить что файл в правильной папке
5. **Быстрое обнаружение:** При ошибке "Cannot find module" сразу проверить физическое расположение файла через `find_by_name`

**Индикаторы проблемы:**
- TypeScript: "Cannot find module" после успешного npm install
- Команды cd/ls работают, но файл не находится
- Наличие двух папок с похожими именами (проверять через `list_dir`)
