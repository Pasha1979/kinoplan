## 🧠 Ключевой архитектурный принцип: Двунаправленная связь Calendar ↔ Модули

> Это уникальное конкурентное преимущество КиноПлана. Нигде у конкурентов этого нет в удобном виде.

### Принцип работы:

```
         КАЛЕНДАРЬ                          МОДУЛИ
    (единая точка входа)            (детальная работа)
           │                                 │
           │   ◄── запланировал скаутинг ──►  │ Локации
           │   ◄── запланировал кастинг  ──►  │ Кастинг
           │   ◄── запланировал примерку ──►  │ Костюмы
           │   ◄── запланировал читку    ──►  │ Собрания
           │   ◄── запланировал трюк     ──►  │ Каскадёры
           │                                 │
           └──────── Dashboard видит всё ─────┘
                   (прогресс + алерты)
```

### Двунаправленность:
- **Из Календаря → Модуль:** планируешь скаутинг в Calendar → событие появляется в модуле Локации, создаётся запись визита
- **Из Модуля → Календарь:** утверждаешь примерку в Костюмах → она автоматом блокирует дату в Calendar
- **Dashboard видит всё:** агрегирует данные всех модулей и показывает общий прогресс + алерты

### Smart Alerts — система умных напоминаний:

Dashboard автоматически считает критические ситуации и показывает их:

```
⚠️  Утверждено 20 из 100 локаций, до съёмок 10 дней — нужен срочный скаутинг
⚠️  Пиротехника в сц.47: разрешение МВД не подано, съёмка через 3 недели
⚠️  Кастинг: 5 ролей не закрыты, ближайшая съёмка с ними через 2 недели
⚠️  Костюмы: примерка актёра Иванова не запланирована, роль уже утверждена
⚠️  VFX-супервайзер не назначен на сц.89 (CGI), съёмка через 30 дней
```

### Структура алерта:
```ts
interface SmartAlert {
  id: string
  projectId: string
  severity: 'critical' | 'warning' | 'info'  // красный / жёлтый / синий
  module: string           // 'locations' | 'casting' | 'costumes' | ...
  text: string             // человекочитаемый текст
  daysUntilDeadline?: number
  actionLabel?: string     // 'Запланировать скаутинг →'
  actionRoute?: string     // '/project/xxx/locations'
  dismissible: boolean     // можно ли скрыть
}
```

### Правила генерации алертов (примеры):
| Условие | Порог | Уровень |
|---------|-------|---------|
| Локации: утверждено < 50%, до съёмок < 30 дней | авто | 🔴 critical |
| Локации: утверждено < 80%, до съёмок < 14 дней | авто | 🔴 critical |
| Пиротехника: разрешение не подано, съёмка < 21 день | авто | 🔴 critical |
| Кастинг: роль не закрыта, актёр нужен < 14 дней | авто | 🟡 warning |
| Костюм: примерка не запл., актёр утверждён | авто | 🟡 warning |
| VFX: супервайзер не назначен, съёмка < 30 дней | авто | 🟡 warning |
| Задача просрочена | авто | 🟡 warning |

## Планируемые модули — полный перечень

### Модуль «Сценарий»
**Аналитика после импорта:**
- Кол-во сцен (INT/EXT, День/Ночь)
- Уникальные персонажи + хронометраж экранного времени каждого
- Уникальные объекты/локации
- Элементы: реквизит, костюмы, транспорт, спецэффекты, VFX
- % разобранных сцен

### Модуль «Кастинг»
- Список персонажей → статус утверждения (кандидаты / утверждён / отклонён)
- Контактная карточка актёра
- DooD мини-виджет: занятость по дням

### Модуль «Локации» (скаутинг)

#### Откуда берутся объекты:
- Источник — сценарий: слаглоны ТИПА `ИНТ. КВАРТИРА МАРИНЫ — ДЕНЬ`, каждый уникальный — свой объект
- Один сценарный объект = несколько кандидатов-локаций, потом утверждается одна

#### Структура данных:
```ts
// Объект из сценария
interface ScriptLocation {
  id: string
  scriptName: string         // 'ИНТ. КВАРТИРА МАРИНЫ'
  type: 'INT' | 'EXT'
  timeOfDay: 'DAY' | 'NIGHT' | 'DUSK' | 'DAWN'
  sceneCount: number         // колько сцен с этим объектом
  projectId: string
}

// Кандидат / утверждённая локация
interface Location {
  id: string
  scriptLocationId: string   // связь с объектом сценария
  name: string               // 'Квартира на Арбате'
  address?: string
  status: 'candidate' | 'scouted' | 'approved' | 'rejected'
  photos: string[]           // пути к фото
  notes?: string
  projectId: string
}

// Скаутинг v1 (простой)
interface ScoutVisit {
  id: string
  locationId: string
  date: string               // ISO
  status: 'planned' | 'done'
  notes?: string
  projectId: string
}

// Скаутинг v2 (будущее, зафиксировать):
// - Маршрутный лист дня: несколько объектов в день, время на каждый
// - Состав группы скаута
// - Печать плана скаута / экспорт PDF
// - Интеграция в Calendar View (обычный тип дня ShootingDayType = 'scouting')
```

#### Жизненный цикл объекта:
```
Сценарий → Список объектов → Кандидаты → Скаутинг → Утверждение → Адрес
(auto)        (список)     (candidate)  (scouted)    (approved)   (реальный)
```

#### Три статуса для Dashboard виджета (как диаграмма съёмок):
- ✅ **Утверждены** (approved) — оранжевые
- 🔍 **На скаутинге** (candidate + scouted) — фиолетовые
- ❌ **Не найдены** (0 кандидатов) — серые
- Прогресс-бар: % утверждённых из всех

### Модуль «Костюмы» (примерки)

#### Логика:
- Источник персонажей — сценарий (те же, что в кастинге)
- У каждого персонажа один или несколько **образов** (костюмов): «Образ 1 — рабочий», «Образ 2 — праздничный»
- Примерка планируется после утверждения актёра → связь: `Персонаж → Актёр → Образ → Примерка`
- Примерка также может быть просто событием в Calendar View без привязки к персонажу

#### Структура данных:
```ts
// Образ / костюм персонажа
interface Costume {
  id: string
  projectId: string
  characterName: string      // персонаж из сценария
  actorName?: string         // утверждённый актёр
  outfitName: string         // 'Образ 1 — повседневный'
  status: 'design' | 'production' | 'fitting' | 'approved' | 'rejected'
  notes?: string
  photos: string[]
}

// Примерка
interface FittingSession {
  id: string
  projectId: string
  costumeId?: string         // если привязана к образу
  characterName?: string     // если привязана к персонажу
  actorName?: string
  date: string               // ISO
  time?: string              // '10:00'
  duration?: number          // минут
  status: 'planned' | 'done' | 'cancelled'
  notes?: string
}
```

#### Жизненный цикл образа:
```
Сценарий → Персонаж → Разработка образа → Пошив/подбор → Примерка → Утверждение
(auto)                  (design)          (production)    (fitting)   (approved)
```

#### На Dashboard (в модуле Пре-продакшн):
- Прогресс-бар: % утверждённых образов из всех
- Три строки: ✅ утверждено / 🪡 в работе/примерке / ✏️ в разработке
- График примерок — ближайшие примерки в Week at a Glance (тип дня `fitting`)

#### Интеграция в Calendar View:
- Тип дня `'fitting'` уже есть в `ShootingDayType`
- Примерки отображаются в «Ближайших 7 днях» зелёным цветом

### Модуль «Транспорт» (игровой)

#### Логика:
- Источник — сценарий: теги транспорта в разбивке сцен (автомобиль, мотоцикл, поезд и т.д.)
- Игровой транспорт ≠ транспорт крю. Это транспорт **в кадре** как реквизит/элемент
- Аналог кастинга/локаций: находим кандидатов → утверждаем → фиксируем

#### Структура данных:
```ts
// Транспортная единица из сценария
interface ScriptVehicle {
  id: string
  projectId: string
  scriptName: string         // 'Чёрный Mercedes 1970-х'
  sceneCount: number         // в скольких сценах
  notes?: string
}

// Кандидат / утверждённый транспорт
interface Vehicle {
  id: string
  projectId: string
  scriptVehicleId: string    // связь со сценарным описанием
  name: string               // 'Mercedes W115 1972, госномер А111АА'
  type: 'car' | 'moto' | 'truck' | 'train' | 'boat' | 'other'
  status: 'candidate' | 'inspected' | 'approved' | 'rejected'
  owner?: string             // арендодатель / владелец
  rentalCost?: number
  photos: string[]
  notes?: string
}
```

#### Жизненный цикл:
```
Сценарий → Описание ТС → Поиск кандидатов → Осмотр → Утверждение
(auto)      (список)      (candidate)       (inspected) (approved)
```

#### На Dashboard (в модуле Пре-продакшн):
- Прогресс-бар: % утверждённого транспорта из всего
- Три строки: ✅ утверждён / 🔍 на осмотре / ❌ не найден

### Модуль «Реквизит»

```ts
  cost?: number
  notes?: string
  photos: string[]
}
```

### Модуль «Спецэффекты и Пиротехника»

#### Охват:
- Взрывы, огонь, дым, пиротехника
- Оружие (стрельба, гильзы, вспышки)
- Спецэффекты на площадке (rain rigs, ветер, снег)
- Каждый элемент — к конкретной сцене, требует **разрешения** и **специалиста**

#### Структура данных:
```ts
type SFXType = 'explosion' | 'fire' | 'smoke' | 'weapon' | 'rain' | 'wind' | 'snow' | 'other'

interface SFXElement {
  id: string
  projectId: string
  name: string               // 'Взрыв автомобиля — сц.47'
  type: SFXType
  sceneNumbers: string[]
  specialist?: string        // пиротехник / спецэффекты
  status: 'planned' | 'permitted' | 'ready' | 'completed'
  permitRequired: boolean    // нужно ли разрешение МВД/МЧС
  permitStatus?: 'not_filed' | 'filed' | 'approved'
  notes?: string
}
```

#### Особенность:
- Разрешения МВД/МЧС — отдельный статус и дедлайн

#### На Dashboard: % готово · 🔴 требуют разрешения (красный бейдж если не подано)

```ts
  type: StuntType
  sceneNumbers: string[]
  coordinator?: string       // каскадёр-координатор
  status: 'planned' | 'rehearsed' | 'approved' | 'completed'
  rehearsalDate?: string     // ISO — дата репетиции трюка
  notes?: string
}
```

### Модуль «VFX / CG»

#### Охват:
- VFX (визуальные эффекты) — постпродакшн, но планируются в пре-продакшне
- CG (компьютерная графика) — полностью CGI-сцены или элементы
- Каждый VFX-элемент требует: тех. задание, supervising, бюджет, дедлайн

#### Структура данных:
```ts
type VFXType = 'compositing' | 'cgi' | 'matte_painting' | 'motion_capture' | 'de_aging' | 'other'

interface VFXShot {
  id: string
  projectId: string
  name: string               // 'Взрыв здания — сц.89 (CGI)'
  type: VFXType
  sceneNumbers: string[]
  complexity: 'low' | 'medium' | 'high'  // сложность = влияет на бюджет
  studio?: string            // VFX-студия / фрилансер
  status: 'brief' | 'in_progress' | 'review' | 'approved' | 'delivered'
  deadline?: string          // ISO
  cost?: number
  notes?: string
}
```

#### Особенность:
- VFX планируется в пре-продакшне, делается в постпродакшне
- На площадке: VFX Supervisor должен быть на съёмке VFX-сцен → строка в вызывном
- Интеграция в стрипборду: VFX-сцены помечаются особым тегом

#### На Dashboard: % VFX шотов в работе/готово · сколько шотов всего · сложность

### Модуль «Собрания» (Meetings)

> Собрания — отдельный модуль, т.к. у каждого типа собрания своя повестка, свой состав участников и своя фиксация прогресса.

#### Типы собраний:
| Тип | Описание | Кто вызывается |
|-----|---------|---------------|
| 📖 **Читка сценария** | Общая читка с группой | Вся группа / КПП |
| 📖 **Читка КПП** | Читка с ключевыми позициями | Режиссёр, актёры, операторы, цеха |
| 📍 **Собрание по локациям** | Что смотрели, что решили, план скаута | Режиссёр, лок.менеджер, художник |
| 🎭 **Собрание по кастингу** | Обсуждение кандидатов, решения | Режиссёр, кастинг-директор |
| 👗 **Собрание по костюмам** | Образы, примерки, сроки | Режиссёр, художник по костюмам |
| 📦 **Собрание по реквизиту** | Список, статусы, дедлайны | Режиссёр, реквизитор |
| 💥 **Собрание по СФХ/пиротехнике** | Согласование, разрешения | Режиссёр, пиротехник, продюсер |
| 🤸 **Собрание по каскадёрам** | Трюки, безопасность, страховки | Режиссёр, каскадёр-координатор |
| 🎨 **Собрание по VFX** | Шоты, техника, дедлайны | Режиссёр, VFX-супервайзер |
| 🚗 **Собрание по транспорту** | Кандидаты ТС, логистика | Режиссёр, художник по реквизиту |
| 📋 **Общее собрание группы** | Оргвопросы, анонсы | Вся группа |
| 💰 **Собрание по бюджету** | Смета, статьи, перерасход | Продюсер, финансовый директор |

#### Структура данных:
```ts
type MeetingType =
  | 'table_read'     // читка сценария
  | 'kpp_read'       // читка КПП
  | 'locations'      // по локациям
  | 'casting'        // по кастингу
  | 'costumes'       // по костюмам
  | 'props'          // по реквизиту
  | 'sfx'            // по СФХ/пиротехнике
  | 'stunts'         // по каскадёрам
  | 'vfx'            // по VFX
  | 'transport'      // по транспорту
  | 'general'        // общее
  | 'budget'         // по бюджету

interface Meeting {
  id: string
  projectId: string
  type: MeetingType
  title: string              // 'Собрание по локациям №2'
  date: string               // ISO дата
  time?: string              // '10:00'
  duration?: number          // минут
  location?: string          // где проходит (адрес / zoom)
  attendees: string[]        // имена / должности
  agenda?: string            // повестка
  status: 'planned' | 'done' | 'cancelled'

  // Протокол — фиксация прогресса (заполняется после собрания):
  minutes?: MeetingMinutes
}

interface MeetingMinutes {
  summary: string            // что обсудили
  decisions: string[]        // что решили (список)
  nextSteps: string[]        // следующие шаги
  nextMeetingDate?: string   // когда следующее собрание
  attachments: string[]      // файлы / фото с доски
}
```

#### Жизненный цикл:
```
Запланировано → Вызывной отправлен → Проведено → Протокол заполнен → Следующие шаги в задачи
  (planned)       (callsheet sent)     (done)      (minutes filled)    (→ taskStore)
```

#### Интеграция:
- Собрание в Calendar View = тип дня `'meeting'`
- Из собрания → автоматически создаётся Task для каждого «следующего шага»
- Из собрания → можно создать Вызывной (список участников уже заполнен)
- Протокол собрания привязан к соответствующему модулю (локации, кастинг и т.д.)
